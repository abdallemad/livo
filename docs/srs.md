# Software Requirements Specification (SRS) — Livo MVP

> الإصدار: 0.1 · التاريخ: 29 أكتوبر 2026
> النطاق: MVP لمنصة خدمات منزلية وبناء (مدينة واحدة، 3–5 فئات خدمات)
> الأولويات بنظام MoSCoW: **M** = Must (لازم) · **S** = Should (المفروض) · **C** = Could (لو في وقت) · **W** = Won't في الـ MVP

---

## 1. مقدمة

### 1.1 الغرض
توثيق المتطلبات الوظيفية وغير الوظيفية لـ MVP منصة Livo، بحيث تكون مرجع للتصميم والتطوير والاختبار.

### 1.2 النطاق
منصة ويب (Responsive / PWA) من **4 أجزاء**:
1. **Marketing Site** (موقع تسويقي عام)
2. **Customer Dashboard** (لوحة العميل)
3. **Provider Dashboard** (لوحة المزود)
4. **Admin Panel** (لوحة إدارة، *إضافة مني*: مش معقول نشغل المنصة من غيرها، لأن أي تحقق من مزودين أو حل نزاعات محتاج واجهة)

### 1.3 تعريفات
| المصطلح | المعنى |
|---|---|
| Customer | العميل اللي بيطلب الخدمة |
| Provider | مقدم الخدمة (فني/شركة صغيرة) |
| Request | طلب خدمة من العميل |
| Quote | عرض سعر من المزود على طلب |
| Booking | حجز مؤكد بين عميل ومزود |
| Escrow | حجز المبلغ لحد إتمام الشغل |

### 1.4 افتراضات (محتاجة تأكيدك)
- A1: الإطلاق في مدينة واحدة.
- A2: الواجهة عربي RTL، مع إمكانية إضافة إنجليزي لاحقاً.
- A3: العملة جنيه مصري.
- A4: **توصيل المطارات خارج الـ MVP** (نشاط نقل منفصل بمتطلبات ترخيص وسلامة).
- A5: الدفع في MVP: **أونلاين عبر بوابة دفع محلية + كاش عند الإنجاز** (القرار النهائي والتكامل التقني لازم يتأكد من بوابة الدفع والجانب القانوني).

## 2. وصف عام

### 2.1 أدوار المستخدمين

| الدور | الصلاحيات |
|---|---|
| **Visitor** | تصفح الموقع، الخدمات، المزودين (ملفات عامة) |
| **Customer** | إنشاء طلبات، استقبال عروض، حجز، دفع، تقييم |
| **Provider** | إنشاء ملف، إدارة خدمات، تقديم عروض، تنفيذ، تحصيل |
| **Admin** | إدارة كاملة: تحقق، فئات، نزاعات، تقارير |

### 2.2 نموذج الخدمات (هجين)
- **النوع A: Fixed-Price Service**: المزود يعرض خدمة بسعر محدد (زي "تركيب نجفة 350 جنيه")، والعميل يحجز مباشرة.
- **النوع B: Quote-Based Project**: العميل يكتب طلب مشروع، والمزودين المناسبين يقدموا عروض، والعميل يختار.

### 2.3 دورة حياة الطلب (State Machine)

```
Draft → Open → (Quotes Received) → Accepted → Paid/Escrowed
      → In Progress → Completed → Reviewed → Closed

الاستثناءات: Cancelled · Disputed · Expired
```

## 4. قصص المستخدم الأساسية (Core User Flows)

### Flow 1: حجز خدمة بسعر ثابت
1. العميل يبحث عن "تسليك حوض" → يختار خدمة مزود → يحدد موعد وعنوان.
2. يدفع (أو يختار كاش) → يتأكد الحجز.
3. المزود يستلم إشعار → يقبل.
4. المزود ينفذ → يعلّم "تم" → العميل يؤكد.
5. يُحرر المبلغ للمزود (بعد خصم العمولة) → العميل يقيّم.

### Flow 2: طلب مشروع (مثلاً تبليط غرفة)
1. العميل ينشئ طلب: وصف + صور + مساحة تقريبية + منطقة.
2. المزودين المطابقين يستلموا إشعار.
3. كل مزود يقدم عرض (سعر + مدة + ملاحظات).
4. العميل يقارن ويقبل واحد.
5. (اختياري) معاينة قبل التثبيت → تعديل السعر بموافقة الطرفين.
6. دفع مقدم/على مراحل → تنفيذ → تأكيد → تقييم.

### Flow 3: تسجيل مزود
1. يسجل برقم الموبايل → يكمل الملف → يرفع مستندات.
2. الأدمن يراجع → يقبل/يرفض مع سبب.
3. بعد التفعيل يقدر يضيف خدمات ويستقبل طلبات.

## 8. قواعد العمل (Business Rules)

- BR-01: العمولة تُحسب على قيمة الحجز وتُخصم من المزود (النسبة قابلة للتعديل من الأدمن).
- BR-02: لا يظهر رقم تليفون أي طرف للآخر قبل تأكيد الحجز.
- BR-03: لا يمكن للعميل تقييم حجز غير مكتمل.
- BR-04: المزود بتقييم أقل من حد معين لعدد معين من الحجوزات يدخل مراجعة.
- BR-05: الطلب المفتوح بدون عروض يخلص صلاحيته بعد مدة قابلة للضبط.
- BR-06: سياسة الإلغاء تعتمد على الوقت المتبقي قبل الموعد (تتحدد تفصيلاً لاحقاً).
- BR-07: في المشاريع، أي تعديل سعر بعد المعاينة يحتاج موافقة صريحة من الطرفين.
- BR-08: المبلغ المحجوز لا يُحرر للمزود إلا بعد تأكيد العميل أو انتهاء مهلة اعتراض محددة.

## 10. خارج نطاق الـ MVP

- تطبيقات موبايل Native
- توصيل المطارات / أي خدمات نقل
- متجر مواد بناء أو قطع غيار
- اشتراكات المزودين / إعلانات
- تتبع حي
- شركات بفرق وصلاحيات متعددة
- ذكاء اصطناعي لتقدير الأسعار (فكرة ممكنة لاحقاً)
- دعم عدة مدن/دول

## 12. أسئلة مفتوحة قبل التثبيت

1. المدينة والفئات الأولى؟
2. الدفع في MVP: أونلاين + كاش ولا واحد بس؟
3. هل المعاينة المجانية جزء من النموذج (زي Sal7lyy)؟
4. نسبة العمولة المستهدفة ونموذج الدفع على مراحل؟
5. هل في فريق تقني أو هنحتاج نحدد ميزانية وتقدير زمني؟
6. إيه الكيان القانوني للمنصة (شركة مسجلة)؟ ده مؤثر على الدفع والتراخيص.
